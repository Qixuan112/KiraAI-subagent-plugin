# SubAgent — 子代理插件 v1.1.3

让你的 AI 可以把活"外包"给一群专业小助手（子代理）：代码专家、写作专家，或你自己定义的任何角色。它们有自己的人格、工具、模型，在后台默默干活，干完了你的 AI 会主动跟你汇报——**全程不会卡住正常聊天**。

---

## 一分钟上手

1. 安装插件并启用。
2. 打开 webui 的**人设界面**，你会发现多了两个新人设：「子代理-代码专家」「子代理-写作专家」——这就是两个默认子代理，人设内容随便改。
3. 直接在聊天里试试：
   - 对 AI 说："帮我审查一下这段代码" → 她会自动派出代码专家，完成后主动向你汇报。
   - 或者发命令：`/子代理1 帮我写一个贪吃蛇小游戏` → 直接派活，不用经过 AI。
   - 干的活不满意想停：`/停止子代理`；想让它接着做：`/继续子代理 任务ID`。

就这么简单。想深入了解，往下看。

---

## 它是怎么工作的？

### 以前（v0.1）的问题

旧版是"同步"的：AI 派出子代理后，整条对话就被卡住，子代理干多久你就等多久，不适应kira系bot常见的聊天环境，体验很差。

### 现在（v1.0）：异步派发 + 主动汇报

```
你发消息 → AI 派出子代理（1秒不到）→ AI 继续正常陪你聊天
              ↓ 子代理在后台干活
子代理干完 → 结果悄悄塞进你的消息队列 → AI 看到后主动开口：
            "你刚才让它做的那个东西弄好啦，结果是……"
```

如果你的消息正好和子代理的结果"撞"在同一批，AI 一次思考就一起处理了，更省更快。

### 任务的一生

`排队 → 运行中 → 完成 / 超时 / 已停止`

- 步数用完、超时或出错时，子代理会**强制做一次收尾汇报**："做到了哪、卡在哪"，不会白干一场。
- 被停止的任务会保留现场 30 分钟（可调），随时可以让它**接着做**。

### 权限和主 AI 完全一致

子代理干活时用的是**你会话的真实身份**：你在文件插件里没放行 `exec`（执行命令），子代理也用不了；你放行了，它才能用。一处配置，两边一致。

## 两种方式使用子代理

### 方式一：让 AI 自己安排（推荐）

直接用自然语言提需求，AI 会自己判断要不要派子代理、派哪个。她还有这些"管理工具"：

| 她能用的工具 | 干什么 |
|---|---|
| 列出/匹配子代理 | 列出全部子代理；还能按任务关键词模糊匹配，命中时附人设摘要，帮她派活派得更准 |
| 派生子代理 | 后台派出任务，立刻告诉你任务ID；她可按任务难度临时指定本次步数（工具描述里带参考刻度：简单 15 步左右、一般 15-20 步、复杂 20-25 步），填小了会被"AI设置步数下限"抬上来 |
| 查询进度 | 看看干到哪一步了（默认 20 秒内不许重复查，防止她犯呆一直问） |
| 停止 / 继续 | 你说"让它停下""让它接着做"，她都能办 |
| 创建子代理 | 临时创造一个专家（比如"翻译专家"） |
| 保存为人设 | 觉得某个专家好用，就把它存进 webui 人设长期用（创建时或事后都可以决定） |

> 💡 **小贴士：主动告诉 AI 步数预算**
>
> 目前 LLM 在缺乏经验的情况下，分配给子代理的步数往往偏保守（实际上就是并不总能理解某类任务应该花多少步来完成）。你在布置任务时，不妨加一句"请在 X 步以内完成"，比如"帮我写一个贪吃蛇小游戏，**20 步以内完成**"。这样 LLM 能更好地安排任务节奏，通常效果会好很多——至少能保证在步数用完前交出一个真正的结果（不过不保证质量 2333）。
>
> 这个技巧对**命令式派活**（`/suba1 任务内容`）同样适用：命令走的是默认步数，你可以在任务描述里明确要求"用 N 步完成"，插件会按你要求的步数（同时受硬上限约束）去执行。

### 方式二：聊天命令（更快，不经过主LLM）

| 命令 | 作用 |
|---|---|
| `/suba1 任务内容` 或 `/子代理1 任务内容` | 派默认列表里第 1 个子代理去干活 |
| `/stopsuba` 或 `/停止子代理` | 停止全部任务；后面加任务ID或序号就停指定的 |
| `/resumesuba 任务ID或序号 [新指示]` 或 `/继续子代理 ...` | 让停下的任务带着保留的上下文接着做，可补充新指示。序号对应列表（启用协调者时=协调者列表，自动继续它最近完成的任务） |

命令完全不走主LLM处理，秒响应，节省token。所有命令词和提示语都能在设置里改成你喜欢的。

> 已启用协调者时：`/suba1` 起的序号对应**协调者列表**（普通下级不再接受命令直派，由协调者安排）。

## 协调者：让子代理管子代理（可选，默认关）

日常任务一个子代理就够了。但遇到"写三篇报告并互相审查"这种多步骤、多角色的大工程，可以打开**协调者**——一个"管其他子代理的子代理"：

```
主 LLM ──只把任务交给──> 协调者 ──自行分派──> 下级子代理（可多个并行）
```

- 开启后，主 AI **只跟协调者沟通**；协调者自己拆解任务、派出下级、跟踪进度、审查结果，直到真正完成才交付。
- 协调者**异步并行**派下级：一步内连派多个，全部后台同时跑，再用收集工具一次性收齐结果。
- 协调者可以**按需创建新下级**（受人设分组「允许创建子代理」总开关约束；是否保存成人设有独立开关，内存级下级在它任务结束时自动回收），但**不能**再派协调者、不能删子代理；主 AI 也不能自创建协调者（只来自设置里的协调者人设列表）。
- 内置预设「子代理-规划师」开箱即用；协调者人设在 webui 人设库可见可改，但**不会**混进普通子代理列表。

一次典型协作的时间线（你说："写三篇报告并审查"）：

```
主 AI 1 秒派出协调者，继续陪你聊天
  └─ 协调者第1步：同时派出 写稿A / 写稿B / 写稿C（三个并行跑）
     第2步：收集工具等齐三份稿件
     第3步：派出一个未参与写稿的下级做独立审查
     第4步：收集审查意见 → "报告B有数据错误"
     第5步：派返工B + 收集
     第6步：汇总三份合格报告，交付
主 AI 收到协调者结果，向你汇报
```

**防烂尾三保险**（协调者不会丢下下级就跑）：

1. 它想收尾时如果还有下级没交付 → 系统拦截并提醒，强制它继续；
2. 它被停止/超时/出错 → 它派出的下级全部级联取消，不留孤儿任务；
3. 下级结果**不打扰你和主 AI**，只经收集工具回流给协调者。

**二次沟通**：协调者任务完成后现场保留 60 分钟（可调），期间用 `/resumesuba1 再补充一点xxx`（序号对应协调者）或让主 AI `resume_subagent` 接着聊，它记得之前拆过的任务和全部对话上下文。

> 💡 协调者本身不占用并发额度（全局/单会话），下级不会因为协调者占位而排队。若要多个下级真正并行，把并发配置调到你期望的并行数量即可。

## 设置项说明（webui → 插件设置）

### 📌 常规

| 设置项 | 默认值 | 大白话说明 |
|---|---|---|
| 启用会话 | 空 | 想让哪些群/私聊能用子代理，填 `<适配器>:<gm/dm>:<会话ID>`；空=都能用（这是第一组第一项，最先看到它） |
| 调用模式 | async（异步） | 异步=派出后 AI 照常聊天，干完汇报；同步=AI 原地等它干完（不推荐） |
| 结果投递 | to_main_llm | 选这个：AI 收到结果后主动向你汇报；选 direct_send：结果直接发给你，AI 不参与 |
| 合并窗口(毫秒) | 100 | 子代理交结果前等这一小会儿，争取和你的消息"拼车"一次处理。0=不等 |
| 全局最大并发 | 10 | 所有群/私聊加起来最多同时跑几个子代理，多的排队 |
| 单会话最大并发 | 5 | 一个会话最多同时跑几个，0=不限 |
| 默认最大步数 | 20 | 子代理干一个任务最多思考几轮 |
| AI设置步数下限 | 15 | 主 AI 给子代理定步数时总爱保守地填 5，会被抬到这个下限。0=不限制。只约束 AI 填的值；插件默认值和你手动配置的不受影响 |
| 步数硬上限 | 25 | 不管谁设置，都不能超过这个数（最终话语权在你） |
| 默认超时(秒) | 300 | 单个子代理任务的总超时（每个任务独立计时），干这么久还没完就强制收工（见下方重要提示） |
| 强制收尾汇报 | 开 | 超时/出错/步数用尽时，也必须交代"做到哪了" |
| 收尾调用超时(秒) | 60 | 收尾那次 LLM 调用带完整任务上下文，慢服务商（如部分 DeepSeek 代理）要给大一点，否则会收尾失败丢失汇报 |
| 清理结果消息标签 | 开 | 投递前剥掉结果里的 `<msg>/<text>` 容器标签（子代理常把框架消息标记当文本输出，不剥会在群里原样显示标签）。`<file>` 等媒体标签保留，与 xml_tag_fixer 插件互补不冲突 |
| 进度查询最小间隔(秒) | 20 | 防止 AI 呆循环反复查进度。0=不限制 |

> 💡 **使用技巧：布置任务时说一步数**。LLM 在缺乏经验的情况下，给子代理分配的步数往往偏保守（它并不总能准确理解某类任务该花多少步）。你布置任务时可以加一嘴说明，比如"……**在 15 步以内完成并发出来**"——命令式（`/子代理 3 xxx，15步以内完成`）和让主 AI 派工时都适用。这样能更好地指导她安排，通常效果明显更好：至少有益于在步数耗尽前交出一个真正的结果（质量嘛，不保证 2333）。

> 📎 **子代理发图/发文件**：子代理在结果末尾写 `<file type="image">路径</file>`（也支持 record/video/file）即可附带真实附件——命令直发模式下插件会把它解析成真正的图片/文件发出去；经主 AI 汇报时主 AI 也能凭路径自行发送。系统简报和收尾提示词都已明确告知子代理这一用法。路径支持绝对路径、`data/` 相对路径、http(s) URL，解析不了的标签会原样保留不丢信息。
>
> 🖼️ **data URI 也支持**：如果子代理给出的是 `<file type="image">data:image/png;base64,...</file>` 这种内嵌数据（常见于浏览器 Canvas 画图路线），插件会在投递前**自动解码落盘到 `data/temp/`** 再作为真附件发出，不会把 base64 刷到群里；svg 图自动降级为文件发送（QQ 不支持 svg 渲染）；损坏或超 25MB 的数据会替换为一句说明而不是原文刷屏。


> ⚠️ **重要：超时是两层，别搞混**
> - **任务总超时**（上面的「默认超时」，本插件管）：子代理整个任务最多跑多久；
> - **单次工具调用超时**（下面「子代理单次工具超时」，本插件管，默认 120 秒）：子代理每调一次工具（exec、读写文件等）最多等多久。已与框架 webui 的「工具调用超时」**解勾**，不再需要去改框架设置；填 0 则跟随框架设置。
>
> ⚠️ **升级注意**：KiraAI 会把安装时的 schema 默认值**写入插件配置文件并永久保留**——升级插件不会覆盖你已有的旧默认值（例如旧版的总超时 120 秒）。升级后请到 webui 插件设置里**手动确认**「默认超时」等数值是你要的值。
>
> （插件自身会做一次迁移：早期 AI 创建的子代理存档里被写死的 `timeout: 120` 会在加载时自动改为"跟随插件默认值"，无需手动处理。）

### 🤖 可选模型

决定 AI 可以给子代理安排哪些"大脑"。每行一条，格式：

```
提供商名;模型名;它擅长什么(可不填)
```

- **留空** = 只能用 webui 设置的快速模型；
- **填了** = 只能用列表里的。想继续用快速模型，就按同样格式把它**真实的** `提供商;模型` 加一行（到 webui 模型配置里看一眼就知道了；AI 查询模型列表时也会告诉你它的真实标识）。

例子：

```
Agnes（CN）;agnes-2.5-flash;代码 推理
deepseek官方;deepseek-v4-pro;写作 翻译
siliconflow;Qwen/Qwen2.5-7B-Instruct;快速通用
```

### 🛠 工具管控

| 设置项 | 默认值 | 说明 |
|---|---|---|
| 工具白名单 | 空 | 填了之后子代理**只能**用这些工具；空=不限制 |
| 工具黑名单 | 发邮件、智能家居等 | 子代理**不许**用的工具。**默认不含 exec**：exec 是否可用完全由文件插件决定（见下），想禁掉手动加回来即可 |
| 关键词匹配 | 开 | 开：填 `exec` 连 `exec_xxx` 一起挡；关：必须名字一模一样才算 |
| 自定义读取/写入路径 | data/files 等 | 子代理专用文件工具能碰哪些目录 |
| 注入框架能力说明 | 开 | 告诉子代理"你有哪些工具、该怎么交作业"，建议开着 |
| exec 非阻塞执行 | 开 | 文件插件的 exec 内部是同步执行命令，**会卡住整个 KiraAI 进程**（所有聊天都会停顿）。开着本开关：子代理的 exec 放到后台线程跑，互不卡、也不卡主进程。建议保持开启 |
| DSML 补执行 | 开 | 部分 DeepSeek 代理会把工具调用漏成 `<｜｜DSML｜｜tool_calls>` 标记文本而不执行，导致任务"假完成"。开启后插件会解析标记、**真正执行**对应工具，并清除结果中的标记。正常结束、步数用尽、**超时/出错后的收尾汇报**所有路径都覆盖。用 DeepSeek 系模型建议保持开启 |
| 子代理单次工具超时(秒) | 120 | 子代理任务内每次工具调用的超时，**与 webui 框架「工具调用超时」解勾**（框架默认会把每次工具调用套进它的 wait_for）。子代理常跑长命令就调大；0=跟随框架 webui 设置 |

> 安全说明：子代理**永远**不能调用"子代理管理"类工具（防止它再生子代理无限套娃）。`exec` 命令执行受官方文件插件管控（allowed_exec_sessions 决定哪些会话能用、exec_deny_list 默认禁 shutdown/poweroff/sudo），子代理用的是**你会话的真实身份**，和主 AI 完全一致。

### 👤 人设集成

| 设置项 | 默认值 | 说明 |
|---|---|---|
| 默认子代理人设 | 内置两个 | 每行 `webui人设名;擅长标签(可空)`。**顺序就是命令序号**：`/suba1`=第1个 |
| 关键词匹配附人设摘要 | 关 | 关（默认）：AI 按任务关键词匹配子代理时只看名称/标签/描述，最省 token；开：人设内容也参与匹配，结果附带人设摘要 |
| 人设摘要字数 | 120 | 上面开关打开时，摘要的最大字数 |
| 允许查看人设详情 | 关 | 开：AI 可以查看子代理完整人设（会多花 token） |
| 允许创建子代理 | 开 | AI 可以临时创造新专家 |
| 允许保存为人设 | 开 | AI 可以把创造的专家存进 webui 人设（**绝不覆盖**你已有的人设，重名自动加后缀） |
| 热加载新保存子代理人设 | 开 | 保存的子代理人设立即加入可用列表。不含你自己创建的无关人设，除非手动填进上方默认列表 |

**放心承诺**：插件装好后会在 webui 人设界面自动创建两个内置人设。如果你已有同名人设，它会自动加后缀（比如"子代理-代码专家-2"），**绝不动你的人设**。你改了它的名字也照样认得（内部用 ID 绑定）；你删了它也不会"复活"（尊重你的删除）。

**来源一目了然**：AI 列出的子代理和命令序号列表里，每个子代理都带中文来源标签——`内置`（插件自带的两个）、`用户人设`（从你自己创建的人设挂接来的）、`AI创建`（主 AI 创造的专家）。你自己的普通人设和子代理人设绝不会混在一起分不清。

|---|---|---|
| 允许继续 | 开 | 停止/超时的任务保留现场，可以接着做 |

### 🧭 协调者

协调者是"管其他子代理的子代理"。开启后主 AI 只把任务交给协调者，由它拆解任务、分派下级子代理、跟踪与审查，直到完成。适合多步骤、多角色协作的复杂任务；日常简单任务无需开启。

| 设置项 | 默认值 | 说明 |
|---|---|---|
| 启用协调者 | 关 | 总开关。开启后主 AI 只能派协调者，命令序号也对应协调者列表 |
| 协调者人设 | `子代理-规划师;规划 拆解 管理` | 每行一条：人设名;标签。独立于默认子代理列表，注册/读取两侧完全隔离 |
| 协调者可用模型 | 空 | 格式同可选模型列表；留空=回退用可选模型列表 |
| 默认步数 | 25 | 协调者单次任务默认步数（它要分派/收集/审查，比下级需要更多步） |
| 步数硬上限 | 50 | **独立于全局硬上限**（全局那个只约束下级子代理） |
| 任务超时(秒) | 900 | 默认 15 分钟：它要走多轮分派/收集/审查，每轮都要等该轮全部下级跑完（同一轮内下级并行） |
| 现场保留时长(分钟) | 60 | 结束后保留多久供二次沟通（resume） |
| 保存协调者创建的下级 | 关 | 关=仅内存存在、重启消失；开=保存为 webui 人设（来源：协调者创建） |

### ⌨️ 命令

| 设置项 | 默认值 | 说明 |

- AI 临时创建并保存的子代理同样持久化。

## 与其它插件的兼容性（桩事件说明）

子代理执行任务时，会在**后台**跑自己的 agent 循环。为了让 file 插件等「按会话作用域」的管控对子代理与主 AI 语义一致（例如 `allowed_exec_sessions` 能认出子代理是替哪个会话干活），子代理的每一步都会用一个**携带发起会话真实 sid 的桩事件**（`_make_stub_event`）去派发：

- `ON_TOOL_RESULT`（每次工具执行后，与框架行为一致）
- `ON_LLM_RESPONSE`（每个 LLM 步，由框架 `AgentExecutor` 派发）

这意味着：**其它插件会看到这些事件**。而桩事件**不会**经过框架的 `ON_LLM_REQUEST`（那个钩子只有 `handle_im_batch_message` 会派发），所以按会话"记账 / 判态"的插件需要自己识别并跳过，否则会把子代理的输出误当成主 AI 的一轮。

**v1.1.3 起桩事件带显式标记**（两个通道都给，任选其一判断）：

```python
is_stub = getattr(event, "is_subagent_stub", False) \
          or (getattr(event, "extra", None) or {}).get("_subagent_stub")
if is_stub:
    return          # 不是主 AI 的一轮：不记账、不判态、不注入
```

已适配的插件（可直接参考它们的实现）：
- **sustained-chat / default-chat(z)**（v2.5.18 / v1.8.9+）：`on_llm_response` 只处理经 `ON_LLM_REQUEST` 登记过的真实批次；带 `_subagent_stub` 标记的直接跳过；
- **随时插话（Midflight）**（v1.3.1+）：运行中状态只由 `ON_LLM_REQUEST` 建立，工具边界遇到外来事件一律忽略（不注入、不还原、不重建）。

> 说明：桩事件的 **sid / 消息形状 / 派发行为**都不变，只是多了一个标记 —— 对既有插件（含依赖真实 sid 的 file 插件）**零影响**。
